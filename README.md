# hack-130eadd9-sa-3
Прототип подбора до трёх подрядчиков с объяснениями. Все профили вымышлены.

## Как проходит запрос

1. Фронтенд отправляет JSON в `POST /api/contractors/search`.
2. FastAPI проверяет типы и диапазоны параметров (`Backend/schemas.py`).
3. `Backend/dataset.py` читает исходный CSV (66 профилей).
4. `Backend/filtering.py` исключает неподходящих кандидатов без ранжирования.
5. `Backend/ai_service.py` получает всех допустимых кандидатов и выбирает до трёх
   в Python: совпадения с пожеланиями, затем начальная цена и ID.
6. OpenAI объясняет уже выбранных. Сервер проверяет ID и опоры объяснения,
   сохраняя вычисленный порядок. Доступен явный `AI_MODE=mock` без сети и ключа.
7. Фронтенд получает исходные карточки из CSV вместе с объяснениями ИИ.

Если кандидатов нет, сервер сразу возвращает пустой список, без обращения к ИИ.
Если кандидатов один или два, ИИ возвращает объяснения для них.

## Запуск пошагово (PowerShell, из корня проекта)

1. Если `.venv` ещё нет: `py -m venv .venv`.
2. Установите зависимости:

   ```powershell
   .venv/Scripts/python.exe -m pip install -r requirements.txt
   ```

   FastAPI — маршруты, Pydantic — проверка данных, Uvicorn — сервер,
   python-dotenv — загрузка `.env`, HTTPX — HTTP-запрос к ИИ и тестирование API.
   CSV обрабатывается стандартной библиотекой Python, без pandas и базы данных.

3. Если `.env` ещё нет, скопируйте `.env.example` в `.env`.
   Укажите `OPENAI_API_KEY` и `OPENAI_MODEL` (модель должна поддерживать Responses API
   и Structured Outputs). Существующий `.env` не перезаписывайте.
   Ключ используется только сервером. Для фильтрации без ИИ он не нужен.
4. Запустите сервер:

   ```powershell
   .venv/Scripts/python.exe -m uvicorn Backend.main:app --reload
   ```

5. Откройте http://127.0.0.1:8000/docs. Выберите маршрут, нажмите **Try it out**,
   вставьте JSON из примера ниже и нажмите **Execute**.

Точка входа — `Backend/main.py`; старые `main.py` и `Backend/main_handler.py`
не используются и оставлены без изменений.

## API для фронтенда

| Метод и адрес | Назначение |
| --- | --- |
| `GET /health` | Проверка, что сервер запущен |
| `GET /api/filters` | Категории, города, языки, форматы и границы календаря |
| `POST /api/contractors/filter` | Только фильтрация, без ИИ и расхода токенов |
| `POST /api/contractors/search` | Фильтрация + рекомендации ИИ |

Оба POST-маршрута принимают одинаковый JSON. Все поля необязательны:

```json
{
  "categories": ["Ведущий"],
  "city": "Алматы",
  "min_price_kzt": 100000,
  "max_price_kzt": 1000000,
  "languages": ["русский"],
  "event_format": "корпоратив",
  "event_date": "2026-10-10",
  "duration_hours": 6,
  "wishes": "Спокойный стиль ведения, без навязчивых конкурсов"
}
```

- Разные фильтры работают одновременно (И). Категории — любая выбранная (ИЛИ),
  языки — все указанные. Регистр и пробелы по краям не влияют на сравнение.
- Пустой массив или отсутствие поля отключает фильтр. Для одиночных полей
  также допустим `null`; пустые строки вместо города/формата/языка не допускаются.
- Цены в тенге сравниваются с `price_from_kzt`, границы включительно.
  Это цена «от», не финальная смета. Не умножаем её на часы — в CSV нет тарифа за час.
- Город сравнивается точно: возможность выезда из текста описания не угадывается.
- Дата исключает занятых. Доступный календарь: 2026-09-23 — 2026-12-31.
  Даты вне периода дают ошибку 422, поскольку доступность неизвестна.
- При заданной длительности профили с пустым `max_hours` исключаются:
  соответствие такому требованию нельзя подтвердить. Без этого фильтра они остаются.
- `wishes` используется для ограниченного текстового сравнения в AI-модуле,
  без дополнительной жёсткой фильтрации.

Ответ `/filter`: `total_candidates`, `matched_candidates`, `candidates` (профили).
Ответ `/search`: те же счётчики и `recommendations` — массив объектов
`{"contractor": { ...профиль из CSV... }, "reason": "Объяснение ИИ"}`.
Порядок массива задаёт Python в AI-модуле. Поля карточки: `id`, `anon_name`,
`categories`, `city`, `price_from_kzt`, `languages`, `event_formats`, `max_hours`,
`busy_dates`, `description` и флаги `city_imputed`, `price_imputed`, `synthetic`.

Пример подключения (добавит разработчик фронтенда):

```javascript
const response = await fetch('http://127.0.0.1:8000/api/contractors/search', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ categories: ['Ведущий'], max_price_kzt: 800000 })
});
const data = await response.json();
if (!response.ok) throw new Error(JSON.stringify(data.detail));
console.log(data.recommendations);
```

Отдавайте фронтенд через HTTP, например в отдельном терминале:
`.venv/Scripts/python.exe -m http.server 5500 --directory frontend`.
Адрес страницы: http://localhost:5500/hackathon%20dataset%20preview.html.
Текущий HTML пока выполняет свою старую локальную фильтрацию, вызов API в него не добавлен.
Для другого порта фронтенда обновите `CORS_ORIGINS` в `.env` и перезапустите API.

Ошибки: `422` — некорректные параметры, `503` — отсутствует конфигурация ИИ
или недоступен CSV; ошибки доступа/квоты OpenAI также дают `503`.
При временном сбое или непригодном ответе возвращается та же выбранная группа
с отметкой «Базовое объяснение без ИИ». Невосстановимые ошибки идут в `detail`.

## Проверка

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Тесты используют настоящий CSV и подставные ответы ИИ, без сети и расходов.
Проверяют фильтры, границы, валидацию запросов, неизвестные/повторные id,
пустой результат, маршруты и ошибки провайдера.

## Что уточнить позже

Версионированный промпт находится в `Backend/prompts.py`. Настройки, ограничения,
запуск и передача backend описаны в [docs/ai/README.md](docs/ai/README.md),
фактические результаты — в [docs/ai/VERIFICATION.md](docs/ai/VERIFICATION.md).
Используется [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Структура ответа проверяется автоматически, достоверность каждого объяснения
требует отдельной оценки. Реальное подключение ещё не проверено;
платная проверка требует локальной настройки ключа/модели и отдельного разрешения.
Это локальный прототип без авторизации и ограничения частоты запросов.
