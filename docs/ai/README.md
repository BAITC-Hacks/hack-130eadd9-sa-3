# AI-модуль: подключение и проверка

Это развитие существующего `Backend/ai_service.py`, не отдельный сервис.
Корневого пакета `ai/` нет. Действует `AI_FINAL_TASK.md`; прежние почасовые
остановки из `AI_Codex_Workplan.md` не применяются. Общие схемы, фильтры,
маршруты и frontend не переписаны. Результаты: [VERIFICATION.md](VERIFICATION.md).

## Для backend-разработчика

```python
from Backend.ai_service import recommend_contractors, AIServiceError

recommendations = recommend_contractors(order, candidates)
```

Синхронный интерфейс сохранён: `SearchRequest` и **все** уже допустимые
`list[Contractor]` → `list[Recommendation]` с прежними `contractor` и `reason`.
Объект подрядчика берётся из входа. Новых обязательных параметров/HTTP-полей нет.
Существующий `Backend.main` уже вызывает эту функцию после своих фильтров.
Пустой список → `[]`, без API, ключа и модели. Число карточек — `min(3, N)`
по уникальным ID. Идентичные дубли схлопываются; конфликтующие → `AIServiceError(422)`.
Входные объекты не изменяются самим сервисом.

Функция остаётся синхронной, как существующий FastAPI `def`-обработчик, который
работает в потоке. Внутри используется один `httpx.AsyncClient` с отменяемым
ожиданием через `asyncio.run`. Если другой backend использует `async def`,
вызывайте синхронную функцию через `asyncio.to_thread`, не прямо в event loop.

## Выбор и его ограничения

В `openai` выбор полностью выполняется в Python:

1. Больше подтверждённых текстовых совпадений с `order.wishes`.
2. Ниже `price_from_kzt`.
3. Лексикографически меньший строковый ID.

Словарь из восьми понятий в `Backend/ai_facts.py`: репортаж, документальность /
фотожурнализм, индивидуальный сценарий, живая музыка, интеллигентный юмор,
спокойный стиль/ведение, цветочное оформление, живые кадры/искренние эмоции.
Одно понятие даёт максимум одно совпадение, только при явном упоминании
и в пожелании, и в описании. Для каждого сохраняется точный фрагмент описания.
Отрицания (`не`, `нет`, `без` и несколько вариантов), рекламные превосходства
и похожие на инструкции предложения консервативно пропускаются.
Это ограниченный лексический разбор, не понимание любого русского текста.
Длинные фрагменты более 260 символов пропускаются. Синонимы вне словаря,
сложные отрицания и все виды внедрения инструкций не распознаются гарантированно.

Без совпадений используются цена и ID. Отсутствие признака означает
«нет подтверждения в тексте», а не «подрядчик не умеет». Имя, длина описания,
порядок CSV и случайные значения не дают преимуществ. Mock намеренно сохраняет
старое поведение: первые уникальные кандидаты в порядке входа, без ранжирования.

## OpenAI и проверка объяснений

Один запрос Responses API на выбранную группу, без автоматических повторов.
HTTPX сохранён; SDK и новые зависимости не добавлены. Передаются заказ,
ID, необходимые факты и короткие цитаты, включая доступность выбранной даты
по каталогу. Полные `busy_dates` и анонимные имена в запрос не входят.

Схема задана через `text.format` с `type=json_schema`, `strict=true`.
Внутренняя модель требует `contractor_id`, `reason`, `evidence_refs`.
Ответ проверяется локально: статус, refusal, JSON, схема, полный набор ID,
повторы, ссылки на факты, русский текст, длина и очевидные противоречия.
Порядок восстанавливается по Python-выбору, даже если модель переставила записи.
При наличии цитаты требуется атрибуция профилю и содержательная связь с цитатой.

Проверяются неподтверждённые числа, некоторые языки/характеристики,
цена «от» вместо почасового/окончательного тарифа, заявления о доступности,
длительности и очевидное противоречие городу. Эти эвристики могут как пропускать
ошибки, так и отвергать допустимые формулировки: это не доказательство истинности
каждой свободной фразы. Нужна ручная оценка настоящих ответов модели.
Оговорки `synthetic`, `city_imputed`, `price_imputed` сервер добавляет сам.
Пустой `max_hours` не превращается в неограниченную длительность.

Официальные страницы, проверенные при реализации:
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini),
[ошибки API](https://developers.openai.com/api/docs/guides/error-codes).
`gpt-4o-mini` уже указан в `.env.example`; доступность этой модели для аккаунта
не проверена. Автоматической замены модели нет.

## Настройки

| Переменная | Значение / назначение |
| --- | --- |
| `AI_MODE` | `openai` по умолчанию; `mock` включается только явно |
| `OPENAI_API_KEY` | Секрет из окружения или локального `.env`, только для openai |
| `OPENAI_MODEL` | Обязательное имя согласованной доступной модели для openai |
| `AI_TIMEOUT_SECONDS` | 8 по умолчанию; допускается 0.01–60 |
| `AI_CACHE_TTL_SECONDS` | 300 по умолчанию; 0 выключает кеш, максимум 3600 |

Backend загружает `.env`; прямой импорт `ai_service` этого не делает.
Переменные окружения имеют приоритет над `.env`. Ключи не помещать в исходники,
логи, тестовые фикстуры или чат. `.env` уже исключён через `.gitignore`.
Раскрытый ранее в чате ключ следует отозвать; новый настроить только локально.

## Ошибки и fallback

Неизвестный режим, неверная числовая настройка, отсутствие ключа/модели,
отклонённый ключ/доступ, недоступная модель и исчерпанная квота → безопасный
`AIServiceError` (обычно 503). Никакого автоматического перехода в mock.

Таймаут, сетевой сбой, временный 429/5xx, refusal, incomplete и непригодный текст
→ та же выбранная группа с отметкой **«Базовое объяснение без ИИ»**.
Это фактический шаблон по каталогу и цитате профиля, не ответ модели.
Причина записывается категорией, без тела ответа или секретов.
Произвольные ошибки программирования и отмена задачи не проглатываются.

Единый бюджет включает подготовку и сетевое ожидание; сетевое ожидание
отменяется целиком, в том числе чтение ответа. Повторов и пауз нет — одна
попытка на промах кеша. Это инженерный ориентир, не гарантия ответа внешнего
API за 8 секунд: планирование ОС, CPU и завершение отмены добавляют накладные
расходы. Возвращённый позже бюджета модельный ответ не кешируется.

## Кеш

В памяти одного процесса — максимум 128 записей, TTL, вытеснение старейшего
неиспользованного элемента. Только проверенные модельные объяснения;
mock, fallback и ошибки не кешируются. Ключ включает заказ (дату и пожелания),
выбранных кандидатов и актуальные данные, модель, режим, версии правил/промпта,
текст промпта и необратимый отпечаток учётных данных для изоляции аккаунтов.
При перестановке входных кандидатов ключ не меняется.

```python
from Backend.ai_service import clear_cache
clear_cache()
```

Доступ защищён блокировкой; хранятся неизменяемые строки, не возвращаемые
объекты карточек. Очистка не отменяется завершившимся старым запросом.
Одновременные промахи могут сделать отдельные запросы; объединения запросов
нет. Кеш не переживает перезапуск и не синхронизируется между workers.

## Запуск и тестирование (PowerShell, корень репозитория)

Чистая установка и команды ниже проверены на Windows / Python 3.14.4:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe -m docs.ai.demo
```

`docs.ai.demo` всегда подменяет транспорт: выводит mock, fallback, тестовый
HTTP-ответ и его кеш. Не расходует токены даже при наличии настоящего ключа.
Тесты блокируют настоящий исходящий HTTP-транспорт. Один smoke-тест запускает
локальный Uvicorn на случайном loopback-порту и затем завершает его.
`PYTHONCASEOK` не нужен: импорты исправлены на фактический пакет `Backend`.

Запуск mock-сервера, не требующий секретов:

```powershell
$env:AI_MODE = "mock"
.venv/Scripts/python.exe -m uvicorn Backend.main:app --host 127.0.0.1 --port 8000
```

Запрос из отдельного PowerShell:

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/contractors/search -ContentType 'application/json' -Body '{}'
```

Сам маршрут с этим телом проверен автоматическим smoke-тестом через Python HTTP-клиент;
команда `Invoke-RestMethod` приведена как эквивалент, отдельно не запускалась.

## Живая проверка — ещё не выполнена

Сначала настройте новый `OPENAI_API_KEY` локально и согласованную модель
(`gpt-4o-mini` в примере не доказывает доступ аккаунта). Затем нужно отдельное
разрешение на максимум 3 реальных запроса, включая повторы. До разрешения
не используйте `/search` в режиме openai как проверку.

После разрешения: `AI_MODE=openai`, `AI_CACHE_TTL_SECONDS=0`, перезапуск backend;
не более трёх запросов через настоящий сервис. Зафиксировать модель, число
запросов, время и usage из безопасной диагностики. Fallback не считать успехом.
После проверки вернуть TTL=300. Live-команды сейчас не проверены.

## Известные границы

- Linux/WSL и командный сервер не проверены; WSL здесь не установлен.
- Исходный DOCX задания организаторов отсутствует в текущем репозитории.
- Существующий backend исключает пустой `max_hours`, когда задана длительность.
  Это его прежняя политика; AI её не меняет и не повторяет фильтрацию.
- Общие зависимости не закреплены точными версиями. В проверенной установке
  Starlette предупреждает о будущем отказе от httpx в TestClient; тесты проходят.
- Содержание настоящей генерации, авторизация, квота и live-задержка ожидают проверки.
